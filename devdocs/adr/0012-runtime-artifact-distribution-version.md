# ADR 0012: Use the panel-solvers distribution version in runtime artifacts

- Status: Accepted
- Date: 2026-08-15
- Supersedes: ADR 0007's Summary CSV and VTP version-metadata decision

The distribution-name spelling in this record is superseded by
[ADR 0013](0013-canonical-project-identity.md). The `solver_version` provenance,
schema, value, and case-signature decisions remain in force.

The best-effort direct-Python version exposure is superseded by
[ADR 0014](0014-remove-legacy-direct-python-api.md). The historical values remain
private inputs to legacy signature reconstruction.

The historical-value signature inputs and legacy-signature matching portions are
superseded by [ADR 0015](0015-remove-legacy-product-identities.md). The current
`solver_version` provenance and canonical signature decisions remain in force.

## Context

During integration of the legacy products, the `fmfsolver` `1.3.8` and
`newtsolver` `1.0.3` compatibility versions remained in Summary CSV and VTP
`solver_version` metadata. After `panel-solvers` is public, those values would
not identify the distribution release that actually generated an artifact.
They would also create unnatural version operations when only one domain's
implementation changes and would conflate distribution provenance with the
historical migration baselines.

## Decision

Runtime artifact `solver_version` is the installed `panel-solvers` distribution
version obtained from distribution metadata. Summary CSV and VTP use the same
value and source. FMF and Hypersonic artifacts generated by one release record
the same version. No domain-, model-, or algorithm-specific artifact version is
introduced.

The legacy values `fmfsolver 1.3.8` and `newtsolver 1.0.3` are migration
baselines, not current domain versions. Private constants may retain those
values where legacy signature reconstruction or best-effort direct-Python
compatibility still requires them.

The canonical `panelsolver.case` version 1 signature and legacy signature
algorithms do not change. The distribution version is artifact provenance and
is not added to case identity.

## Consequences

If only FMF behavior changes in `panel-solvers 0.2.0`, artifacts produced by
both FMF and Hypersonic in that release still record `solver_version=0.2.0`.
The changelog and release notes identify which domain or model changed.

Historical fixtures continue to contain the metadata emitted by their pinned
legacy sources. Current regression comparisons treat `solver_version` as the
intentional metadata transition without rewriting that evidence. Old VTP files
remain readable and match through case ID plus the canonical or legacy case
signature, not through the solver-version string.
